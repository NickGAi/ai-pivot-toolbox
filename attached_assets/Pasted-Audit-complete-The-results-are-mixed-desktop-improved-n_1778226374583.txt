What I can see actually changed on the live site
The good news: the chat widget (LeadConnector) and libphonenumber-min.js are gone from the homepage. The Bunny Fonts duplication is also resolved. That's a real win and is why desktop improved.
The bad news, and the cause of the mobile regression: the main app bundle index-Dfwek-Ke.js is still loaded synchronously without defer or async, and it's now executing more work on the main thread. Lighthouse is showing 8.6 seconds of main-thread work, 4.1 seconds of JS execution, and 20 long tasks on mobile — all dramatically worse than before. The 2,330 ms Total Blocking Time is the killer; that single metric is dragging the score down.
Also, the unused fonts.googleapis.com and fonts.gstatic.com preconnects are still there.
What still needs to be done
The number one fix that wasn't applied: add defer to the main script tag. Currently it's <script src="/assets/index-Dfwek-Ke.js"></script>. It needs to be <script src="/assets/index-Dfwek-Ke.js" defer></script>. This is a one-line change and would have a large impact on mobile.
The bigger issue is that the bundle itself is doing too much work on the main thread when it executes. Lighthouse flagged ~276 KiB of unused JavaScript still in the bundle, and the 20 long tasks suggest the SPA is doing heavy synchronous initialization on mobile (which has a much weaker CPU than the emulated desktop). This needs code splitting / lazy loading of routes and components, which is a bigger refactor.
Other remaining items: remove the unused fonts.googleapis.com / fonts.gstatic.com preconnects, fix the form/select label accessibility issue (still flagged), set longer cache lifetimes (~2 KiB), and reduce document request latency (~15 KiB).
